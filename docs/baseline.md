# 改造前基线与兼容性证据

基线提交：`5ab2ad7f02ea773c9c25a68688f7ce3404060c05`。
测试使用 Node.js v24.19.0 的内置 `node:test`、`vm` 和 `crypto`；无测试依赖。

## 改造前状态

仓库为原生 JavaScript、HTML、CSS 与 vendored Three.js 的静态浏览器游戏；改造前无 README、AGENTS.md、仓库 `.agents/skills`、package.json、构建脚本、类型检查或测试任务。工作区 `/workspace/.agents` 为空。原有 Python 工具用于素材处理，不能视作游戏构建或验收脚本。

玩法值分散在 `map.js`、`actors.js`、`items.js` 与 `game.js`。随机源为 `Math.random()`，没有种子入口；物品 UID 也消耗相同随机源。`view3d.js` 的粒子渲染单独使用随机数，因此旧浏览器运行没有严格的玩法与视觉随机隔离。

已有持久化键：

- `md_warehouse_v1`：物品数组，保留 type、uid、charges 等字段。基线只检查最外层是否为数组，不检查每个条目是否合法。
- `md-skill-meta`：active/passive 技能槽数量；加载时裁剪至允许范围。

未发现完整的地牢进度存档。配置草稿或预览不能覆盖上述键。

## 实际执行的基线测试

```sh
MD_TEST_BASELINE=1 node --test tests/baseline.test.cjs
```

首次执行：10 个测试通过，0 失败、0 跳过。此模式通过 `git show` 读取上方固定提交的源码；不会把工作树改造后的结果当作基线。默认模式读取当前工作树源码和冻结的 `tests/fixtures/default-config-v1.json`。此测试夹具仅用于验证改造前默认玩法，不是配置权威源；设计师后续调数无需修改该夹具。实际生成的 `config/game.json` 由单独测试校验有效性，因此合法调数不会触发历史数值断言。

测试覆盖初始玩家属性、敌人 0.85 倍缩放后的有效属性、楼层敌人概率边界、掉落概率边界、法杖 4–6 次充能、伤害上下界和有效旧仓库载荷兼容。布局使用确定性 LCG：`state = (Math.imul(state, 1664525) + 1013904223) >>> 0`，输出 `state / 4294967296`。

## 证据边界

这些测试锁定默认算法与典型数值，并不证明所有配置组合安全；安全范围与结构/引用校验需要新增专项测试。该 VM 基线不加载 WebGL、不执行真实键盘/鼠标输入，也不验证 Three.js 视觉表现、浏览器存储配额或设备性能。没有原有构建或类型检查可执行，不能将它们记为基线通过。
